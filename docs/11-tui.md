# Greenlight interactive TUI

Greenlight's Ratatui interface is a session conversation and a controller for **the existing Engine**. Both CLI and TUI use the same persisted histories, approval policy, workspace edit journal and fork/restore implementation.

The first [manager Q&A stage](21-manager-qa.md) implements `/ask`, context preview, saved exchanges and validated **unexecuted** forwarding proposals. The composer now names its recipient: Ask manager is read-only; Send & resume delivers literal instructions to the selected ready/blocked step, even when `manager.enabled` is true. The setting suggests a manager question for a fresh draft; it never overrides an explicitly selected recipient. Navigation `/` opens a separate Commands editor for `/resume` and the other control commands. Executing manager routes and the [coordinator contract's](20-conversational-coordinator.md) live instruction inbox remain unimplemented.

```bash
cargo run -- --root /path/to/project tui
cargo run -- --root /path/to/project tui SESSION_ID
```

## Session workspace

The compact header shows the project and labeled state/current step. Details (`c`) opens a read-only run overview with the full goal in blue, current state, roadmap and ownership. The roadmap shows latest recorded states: loops may revisit steps, and it is not a percentage of success. Technical details expands session/branch IDs, current configured model, requested/returned models from the latest dispatch linked to the recorded attempt, pinned-input references and the exact recorded definition. Missing legacy metadata stays Not recorded; current configuration is not presented as historical model evidence. Back/Esc returns through these views to the prior workspace reading position. A session/branch change closes the old details rather than showing another run under its title.

Use `c` → Technical details, or enter `/context`, for a scrollable snapshot of the objective, required outputs, verification verdict, exact pinned input event IDs and approval references. An existing attempt uses its saved definition and manifest; a ready session shows the configuration for its next attempt. Missing legacy metadata stays explicit. Model prose never supplies a verification verdict.

Blocked sessions show a concise cause, impact and next-action overview; Inspect evidence opens the exact recorded cause and Full diagnostic preserves the complete message. `e` opens its exact event, `H` returns to activity, `b` reopens the card, `2` opens artifacts, `i` composes resume instructions, and `r` opens the guarded restart flow. These controls never automatically retry. A live external owner is observation-only; interrupted ownership needs `/recover`, and unfinished native writes need CLI `recover-writes`. Context and evidence remain scrollable with arrows; Escape closes context.

Activity uses concise rows; Enter or a row click opens the selected event's evidence in the available pane, and Enter/Left/Escape returns to the list. Sidebar entries lead with the session goal. The session picker supports search and workflow creation as described below.

## Finding and creating sessions

The session browser is hidden by default. Sessions, Left/Esc from a workspace list, or `f` opens it; at 100 columns or wider it appears beside the still-open workspace, and narrower terminals use a full-width picker. Rows show a goal, labeled status/current step and activity time where space allows. A badge identifies the opened session. Blocked sessions sort first, then latest activity; selected candidate identity survives background reordering.

Search is an explicitly focused blue field with a blinking caret. It matches goals, workflows, steps, statuses and session IDs case-insensitively, including Unicode. Arrows or row clicks select a **candidate only**; Enter/Open selected explicitly switches the workspace after checking that identity still exists. Search, selection and cancellation do not switch sessions, change drafts or execute work. Back/Esc closes browsing and retains the memory-only query; Clear search resets it. Tab reaches browser controls, and Escape leaves controls before closing the browser. Letters/paste remain literal in search; `f` edits the query from list focus. Opening a session starts no workflow and makes no model request.

Successful empty discovery, no search matches, setup problems, discovery failures and an unavailable opened session have different presentations. Discovery/history failures offer read-only retry; keyboard and mouse use the same action. If the opened session or selected candidate disappears, another run is not silently substituted. An active local worker stays with its original session even while another workspace is opened. A pending local approval closes the browser and returns to that worker's owning session, with drafts still scoped to their own session/branch/recipient.

Press `n` to choose a workflow from the project's `.greenlight/workflows/` (or legacy root `workflows/`). Arrows select; Enter opens the goal editor. Invalid workflows show their validation error. Enter a nonempty goal and press **Enter to create and immediately start the session** through the existing engine and approval policy. Back changes the workflow without losing the goal; Cancel/Escape closes creation while retaining its memory-only draft. Clear draft discards that unsent goal. The form revalidates workflow files on submission and retains other sessions' drafts. Creation is disabled while this TUI has an active worker; no separate `/resume` is needed for a new goal.

Goal and composer editors support Left/Right, Up/Down across wrapped rows, Home/End, Delete and Backspace, including Unicode graphemes. Ctrl+J, Alt+Enter or Shift+Enter inserts a newline (terminal support for modified Enter varies). Editable text is blue; labels/hints retain their UI colors. Active goal, composer, session search and activity-filter fields use a real terminal blinking caret and scroll to keep it visible.

The header shows STARTING immediately, then the persisted execution status. TUI-owned model calls request OpenAI-compatible SSE streaming with final usage. The running Activity view gives **Live model output** most of the workspace: at least 90 available columns, compact activity occupies roughly one-third on the left and output two-thirds on the right. Each activity row puts its step and event label on one line; summaries and exact tool evidence open on Enter/click in the right pane. A visible **[Enter] Live output** action returns to the stream. Narrow workspaces stack a short activity list above the larger output pane. The stream shows the latest 64 KiB of unvalidated response text, separately from recorded actions/results. Only a complete response enters normal action validation; truncated/malformed streams fail without executing their partial action or automatically retrying uncertain billable requests. Final provider input/cached-input/output usage remains in the central ledger; absent reports retain the usual estimates/unknowns. Providers that return ordinary JSON instead of SSE still complete normally, but cannot show partial text. Error diagnostics and approval prompts take precedence over the preview. `P` hides/shows output and `Z` switches between the split view and full-width output; both are also in More. Streaming is ephemeral, not an extra event per token; completed responses use the existing history records.


## Main interaction

Open a blocked or ready session. The composer never automatically captures shortcuts. Blocked sessions with recorded failures open a scrollable diagnostic first; inspect it and press Escape to return to navigation. From Sessions use **Enter** to focus the conversation/artifact list. Enter or clicking a row explicitly opens evidence; at wide widths the activity inspector can remain beside the list and follows deliberate selection. Outside the running split view, narrow widths use a full-width reader. Right or Tab focuses the workspace actions instead of implicitly opening evidence. Press **i** or Compose to open the editor. Enter in the detail pane returns to its list. Choose the workflow-step recipient, type instructions and press Enter or Send & resume to resume the agent. Choose Ask manager for read-only questions. While the agent works, its activity appears in the conversation timeline; the TUI refreshes automatically. Direct resume waits for the current worker to stop; read-only manager questions remain available through Ask manager; `/ask` remains available in Commands mode.

Example instruction: `Fix the existing add() bug and rerun verification.`

The default conversation hides routine tool-permission decision records. Press `v` or use `/events` to include them in full history. Tool failures and human workflow checkpoints remain visible; the recorded audit history is unchanged.

The TUI executes resumed sessions in a background worker thread with a separate Tokio runtime and database connection. It does **not** fork a CLI process or bypass the Engine. All shell commands still use the mandatory Bubblewrap sandbox.

Tool permission requests open a centered modal popup over the workspace. It shows the exact request and every valid grant choice: **`y`** once, **`a`** for this process, **`p`** project or **`g`** global where supported, and **`n`** deny. Decision keys submit immediately; Enter never decides. Other workspace shortcuts and background clicks are ignored while the popup is open; arrows/page keys scroll the request. **Esc dismisses the popup without sending any answer. The agent remains blocked waiting for the same decision.** An amber **[a] Review permission** action reopens it; outside text inputs, `a` opens the popup without approving anything. Browsing, Help and composing remain available after dismissal; permission keys outside the popup cannot decide the request. The TUI cannot start another workflow while the local worker remains active.

Project/global choices open a fresh persistent-grant confirmation popup. `y` saves the grant and allows the request; `n` cancels the grant and denies the request. Esc only hides this confirmation, preserving its pending state and saving nothing. Key repeats cannot decide, and decisions are disabled below 40×20; Esc still dismisses. Expired worker requests disappear and cannot be reopened. Human workflow checkpoints retain their separate evidence-review screen and existing `y/n` (Esc declines) controls.

## Semantic activity cards

The default activity list uses compact cards: a title/status, step and short summary; IDs remain in expanded/raw evidence. Execution cards describe recorded facts; optional **Agent intent** cards explicitly label model-authored annotations. Small panes show a single title line; Enter/Right expands the selected card, and Enter/Left/Escape returns. Opening evidence pauses activity following, including when inspecting the latest item. End/G in the list resumes it.

- New tool/command-step outputs link to their exact request and expand both arguments and result/error. Shell cards can show the recorded exit code. Other tools say **returned**, not “success”; file contents or model prose cannot supply an exit code or verification verdict. Old outputs without saved correlation say **unlinked**. Auxiliary `tool.finished` records and routine permission decisions stay hidden in the default list.
- Coding responses may include an optional bounded `activity_title`, such as **Exploring call sites**. A separate **Agent intent** card appears before the requested action, even if approval is pending or the action later fails. Its informational style does not assert success. Enter expands the exact model response and saved annotation; `F` searches the title. Titles never grant permissions or count as verification evidence. Without a supplied title, the existing recorded-fact cards remain unchanged. See [validation and history semantics](13-agent-action-protocol.md#4-optional-activity-title-implemented).
- Verification cards distinguish a failed individual check, recorded command exit, model-authored reviewer report, selected-evidence references and the aggregate policy verdict. A rejected check may coexist with a later aggregate pass under an any-of policy. A model report alone is not displayed as a verified pass.
- File cards identify native write/restore records; `d` opens the matching journal diff. Artifact cards identify a creation event; `o` opens that exact version, even after a newer same-name version exists. Its browser supports provenance and adjacent-version diffs as usual.
- Provider and partial-restore failures use their recorded structured fields. Unknown or malformed records retain raw evidence; invalid tool links become visible diagnostics rather than silently attaching unrelated output.

`v` or `/events` switches to the original raw audit timeline, including request/correlation records; it never deletes events or changes approvals. Expanding a raw row shows that event's original payload. Expanded card/diff evidence uses the same terminal-safe bounded reader, including background preparation for large bodies. Card projections are cached by session, branch and latest immutable event ID; redraws do not repeatedly parse reports. No extra model calls generate titles or summaries.

## Reading state, filtering and export

Activity and artifact tabs retain independent selection, reading/list focus and scroll positions by session and branch. Selections use event IDs and artifact names/version IDs, so a new row does not move an inspected item. Activity retains its follow/pause state and any opened journal diff. Help/context/diagnostic panels have separate temporary scroll; closing them returns to the saved tab position. If a selected record is filtered out or unavailable, the tab uses a visible fallback with its offset reset. A newer same-name artifact resets that artifact's offset rather than applying an older body's position. Positions, filters and drafts are **in memory only** and disappear when the TUI exits. Raw/Markdown visibility settings retain their existing behavior; this is not a persistent bookmarks system.

From activity navigation press **F** to filter event kinds, steps, card titles and summaries with a case-insensitive literal substring (including Unicode). Typing filters cached rows without reading the database or cloning their bodies; normal background polling still updates the source rows. Enter keeps the filter; Escape clears it. To clear an applied filter, press F then Escape. Filters are remembered per session/branch. This searches displayed metadata/summaries, not complete hidden payloads; use a full conversation dump for deep source searches. Lowercase `f` remains session search.

Press **C** from a reading/navigation surface to copy its **full selected text**, beyond preview clipping. Artifact content is the original stored text; artifact-version content uses the selected creation ID; provenance/diff panels export their current report. Activity exports the complete expanded evidence (or raw audit record in raw mode). Help, context, diagnostics and restore previews export their displayed source. Clipboard work runs outside the input loop and confirms success only after the utility accepts the complete input and exits successfully.

Copy uses `wl-copy`, then `xclip`, then `xsel`, with a two-second limit per utility. At least one utility and a working Wayland/X11 desktop session must be available. It targets **the machine running Greenlight**; SSH/cloud sessions do not automatically copy to your local terminal's clipboard. There is no OSC 52 fallback. Missing/failed utilities produce a scrollable diagnostic with CLI-export guidance. The harness sends original text, including control bytes, to the clipboard utility; it does not send the escaped/clipped preview or log document contents.

Press **E** to open the selected text as a private read-only temporary `.txt` snapshot using `VISUAL`, then `EDITOR`, then `vi`. The TUI pauses and hands over the terminal until the editor exits, then redraws and restores input. Editor errors also restore the terminal and show a diagnostic. Editor commands support quoted program paths/arguments via `shlex`; they are launched as argv, not interpolated shell commands. Common Code/Codium/Cursor/Sublime commands receive `--wait` when absent, and gvim/mvim receive `-f`; other GUI editors must be configured to wait for the file to close. Snapshots are cleaned up on normal return, including editor errors. Forced process termination can leave a private temporary file.

Edits to that snapshot are **not imported** into stored artifacts, history, project files or the composer. Save a separate file and explicitly use `put-artifact` if a new artifact version is intended. Editor handoff is refused while this TUI's own worker runs so approval dialogs remain available; copy remains usable during runs. These helpers are explicit local user actions, not sandboxed model-tool calls. C/E are literal text in composer/search/filter inputs and inactive during approvals. Native approval keys and permission semantics are unchanged.

## Failure diagnostics

Worker failures/disconnects, blocked-step reasons, malformed known structured events, missing artifact bodies and partial restores open a concise attention overview. Full diagnostic opens a scrollable complete message; Up/Down scroll it and Escape dismisses it without changing execution state. Typed provider records supply category-specific guidance; model prose never determines the failure category. Polling preserves diagnostic scroll position and does not repeatedly reopen an acknowledged unchanged error. Raw event evidence remains available; unknown event types remain readable rather than being rejected. These panels do not interpret model prose as a verified outcome.

Recover owner rechecks the live lock, expires unanswered approvals and leaves saved grants intact; it never resumes execution. Unfinished native writes expose CLI recovery guidance without executing reconciliation. An externally owned session is observation-only. Known local retry waits show a waiting state without a fabricated countdown.

Restore failures include files changed versus files journaled. A failed restart does not fork, and a restore-then-fork failure is explicitly distinguished. Inspect workspace/history before retrying; a partial restore is not automatically rolled back. Artifact read failures preserve history access.

## Provider failures and retry waits

Provider errors show actionable guidance for credentials, account credit/quota, rate limiting, permissions, invalid requests and provider/network problems. Final failures block the session and appear in the existing diagnostic/history panels. Errors during verification stop the run directly; they cannot trigger a verification-failed workflow retry or detector call.

Eligible rate-limit rejections or connection failures can retry with at most three requests. The activity list records each failure and retry delay. Press `x` in navigation (including a reading/help/diagnostic panel) to cancel a retry wait and stop future provider requests from this worker. It does not interrupt an in-flight HTTP request or stop a tool already running; a returned action may still finish before the next provider-call boundary. `x` stays literal text in the composer/search, and is inactive during approval dialogs. A fresh resume creates a new worker with cancellation cleared. See [provider failures](19-provider-failures.md) for retry/billing limits.

## Token usage

Usage is available from Run details, More, or `/usage` in Commands mode. Its live summary covers all recorded dispatches for the selected session across all branches, including failures and retries. Input, cached input and output retain provider-reported/estimated/mixed/unknown labels. Cached input is a subset of input, not added again. Missing counts/rates remain unknown; cost is unavailable or a Partial estimate with coverage, and currency subtotals remain separate. No recorded requests does not establish that the session was free. Historical calls before the ledger are not backfilled.

Request details opens a list: arrows, Home/End and page keys select; Enter/click opens that exact dispatch. Selection uses request identity across refresh; a missing record is shown as unavailable rather than substituted. Individual details include requested/returned models, status, count sources, cache-creation/reasoning data, captured pricing metadata and technical identity. Full accounting retains per-model/attempt summaries and historical pricing-source/date notes. Back/Esc returns through nested views. C copies the current full text snapshot; request and full-accounting views also expose Copy. Browsing makes no model request, refreshes no prices and writes no history. CLI `usage SESSION_ID --json` remains available for the full ledger.

## Artifacts tab

Press **2** in navigation mode to open the **Artifacts** tab; press **1** to return to the conversation. The left pane lists the most recent version of each artifact on the selected session's active branch, along with its producing step and byte size. The right pane renders headings, emphasis, inline/fenced code, lists, blockquotes and simple pipe tables. Press **m** in navigation mode to toggle between rendered Markdown (the default) and a literal Markdown-source preview; the original stored artifact is never rewritten. Other CommonMark features, hyperlinks and complex table layouts are not yet supported. Arrows and **g/G** select a saved artifact; **Up/Down** scroll the artifact when the detail pane is focused. The selected artifact remains selected when newer versions are registered.

Both preview modes visibly escape terminal controls (including ANSI/OSC escape bytes, C1 controls and bidirectional formatting controls) as `\u{xxxx}` text. CRLF is normalized to newline, a lone carriage return is escaped, and tabs display as four spaces. International text, combining marks and emoji joiners remain intact. Simple table padding uses Ratatui terminal widths; unusually wide cells wrap normally, and alignment beyond the padding budget is not guaranteed. Longer code fences require a matching closing run of at least the opening length with no trailing content.

Preview processing stops at the first of 256 KiB of source/sanitized text, 4,096 source lines or 8,192 sanitized bytes on one line. Both modes show an explicit truncation notice. Tables recognize up to 32 columns, with at most 240 cells of padding width per row; excessive-column tables stay literal. These are display limits independent of the workflow's artifact-size policy. To retrieve the full stored artifact, use `greenlight artifact SESSION NAME > artifact.md`; the CLI output is unfiltered, so redirect it to a file rather than relying on a terminal preview. The literal toggle preserves Markdown syntax, but is not an unfiltered terminal or unlimited export.

Artifacts are inputs to later workflow steps and an important human-review surface. This tab deliberately uses the same branch-aware `Store::artifacts` lookup as the CLI and does not alter artifact content. The default list shows **latest versions**; press `v` for historical versions. To register a manually edited version, use `greenlight put-artifact SESSION_ID NAME --file PATH` from another terminal; direct artifact editing remains a follow-on feature.

## Preview responsiveness

Artifact/version content and expanded activity evidence over 8 KiB or 64 lines are prepared on a background preview worker. While it parses, wraps and prepares the visible viewport, the panel shows **Preparing document preview…** and keyboard input remains active. Moving to another version, toggling Markdown/literal mode or resizing cannot paint a result from the old selection. The worker reuses prepared text and wrapped line counts; an unchanged viewport is reused on redraw. Its input/result queues each hold at most one pending item. Preview limits and terminal escaping are unchanged, and the worker has no engine/store or approval authority.

Short previews use the bounded synchronous path. Storage refresh/blob reads, explicit diff generation and approval-request rendering retain their existing paths; this change does not promise asynchronous execution of every TUI operation. If the preview worker fails, the panel reports that it is unavailable and CLI export/navigation remain available.

## Artifact versions and provenance

In the Artifacts tab, select an artifact and press `v`. The version browser shows saved creation-event IDs, producing steps and UTC timestamps, newest first. It only includes versions visible in the active branch's ancestry at each fork cutoff. Parent changes made after the fork and sibling/session versions remain excluded.

Use arrows to select a version. Enter or a row click opens its content at the available width; Enter again or Left returns to the version list. `o` opens content, `m` toggles literal/Markdown content, `p` opens provenance, and `d` compares the selected version with its immediate older visible version. In reading mode arrows, PgUp/PgDn and Home/End scroll. Escape closes the browser and returns to latest artifacts. Controls are read-only and preserve composer drafts. The inspected creation ID stays pinned when newer versions arrive; changing session/branch closes the browser. Incoming approvals take priority and close it.

Provenance shows the exact creation event, source branch (including inheritance), associated recorded attempt/definition when the creation falls in that step's attempt interval, selected-input consumers and human approval events referring to that exact artifact event. An interval association does not identify whether a human or model authored the content. Unknown/legacy metadata is explicit. Historical approvals describe recorded review, not a fresh authorization or approval of later replacements. Malformed manifests/approval payloads are reported rather than reconstructed from latest names.

Missing blobs show an error for content/diffs while metadata/provenance remains available. The first visible version has no predecessor. Identical bodies are labelled as identical; differing versions use the existing newline-aware unified diff. Unified diff generation is limited to 256 KiB per input; full originals, never clipped previews, are compared within the limit. Result previews retain terminal escaping and display limits.

Export a specific visible version with `greenlight artifact SESSION NAME --event EVENT_ID > version.md`. Without `--event`, the CLI still exports the latest visible version. The event must belong to that artifact, session and active branch ancestry. Exports do not modify history or trigger execution.

## Restart from a historical step

Type `/restart` in the composer. Use arrows to select an earlier **executed** workflow step and press Enter. Greenlight selects the checkpoint immediately before the first recorded attempt at that step, constructs a **guarded workspace restoration plan** from its native edit history, and displays the file changes. Press `y` to apply and fork at that event; `n` or Escape cancels with no modification. This is a real workflow branch, not a text instruction asking the model to pretend it is at a different step.

The restore planner refuses mismatched file snapshots, manual drift, symlinks, and unsupported paths. Its guarantees apply only to recorded native writes/restores, not manual edits or untracked shell operations. Restoration applies individual files; if an error occurs partway through, the error is displayed and the user must inspect the workspace/history. Never retry blindly after a partial restore. Restart does not automatically execute the new branch; send step instructions or run `/resume` in Commands mode.

## Keys

The focus model uses explicit evidence opening: Enter or click opens details, Enter/Left/Escape returns, and move or scroll in the currently focused pane rather than switching into an implicit editor. For an AZERTY-friendly keyboard, **Up/Down** handle ordinary detail scrolling and restart previews; tool/provider popups use arrows/page keys for scrolling; **PageUp/PageDown optionally scroll eight lines**, and Home/End jump to the beginning/end of reading panels. Navigation opens without focusing the composer, even for blocked sessions.

- **Enter/click** opens selected evidence; **Left/Esc** returns or opens/closes Sessions. **Right** focuses the action row. Focused detail content scrolls independently of selection.
- **i** or Compose opens the composer; **Enter** in the composer sends. Enter in detail returns to the list. **Escape** from the composer returns to the previous pane.
- **Ctrl+J** inserts a newline into the composer; **Escape** returns to the previously focused pane.
- **1 / 2 / 3** switch Activity / Artifacts / Edits in navigation mode; **m** toggles rendered Markdown/raw text in Artifacts.
- **Tab/Shift+Tab** enters/cycles workspace action controls; Enter activates an ordinary focused action, Esc returns. More opens a keyboard/mouse action menu. No function keys are required.
- Up/Down and **g/G** or Home/End navigate sessions, events and artifacts when a list is focused; Up/Down scroll line by line when detail is focused.
- **d** displays a journal-backed unified diff for a selected native write or restore; **v** toggles concise/full event visibility.
- **Up/Down** and page keys scroll tool/provider popup requests; ordinary readers and restoration previews use arrows.
- **F** filters activity; **C** copies the full selected text; **E** opens a temporary review snapshot in the editor. All are uppercase navigation keys.
- **h/?** opens contextual keyboard Help; **/help** opens it from Commands mode. Dismiss a tool/provider popup with Esc before opening Help. Help can sit above human review; decision keys cannot decide there, and Esc closes only Help. Expired requests never regain controls. Within Help, Tab reaches Close and Toggle mouse; **M** toggles capture directly. While editing, letters and `?` remain literal text.
- **/restart** chooses the step to restart; **/resume** resumes without extra instructions; **/recover** recovers the selected session's interrupted execution owner without running it; **/events** toggles raw event visibility; **/help** lists shortcuts.
- **q** quits from navigation mode when no agent is running. The TUI intentionally prevents quitting while its own worker is active, to avoid silently abandoning a pending prompt.

## Drafts, following and terminal size

Unsent composer text belongs to the selected session, active branch and recipient (step, manager or command interface). Switching sessions, changing filters, opening help, cancelling restart and returning to an approval's owning session retain each session's draft separately. A new session starts with an empty draft. Drafts remain **in memory only**; exiting the TUI discards them. Long messages scroll to keep the editing caret visible.

Activity initially follows incoming events. Opening evidence or navigating activity pauses following, including when reading the latest event. Background polling preserves that event and its scroll position. In the activity list, End or `G` selects the latest visible event and resumes following; Home or `g` selects the first and pauses. The activity title indicates following/paused. Artifact and diagnostic scrolling remains independent of new activity.

The compact header is used at every size. At narrow widths common header actions use a second navigation row; short button labels fit their available cells. Below 72 columns or 22 rows the open session picker/workspace uses full width; close Sessions to return to the workspace. Wrapped-content scroll bounds are recomputed at the current size, so overscrolling and resizing do not leave a blank reading panel. Below 40×14 it shows a resize notice and retains drafts/selections. Approval requests require at least 40×20; until then decision keys are disabled. Escape hides a tool-permission popup without deciding; human checkpoints retain their explicit decline behavior. Restoring the terminal size restores the pending request. Enter remains inert during approvals at every size.

The wrapped-line calculation uses Ratatui's `unstable-rendered-line-info` feature on the version recorded in `Cargo.lock`; dependency upgrades must retain the resize/scroll tests.

## Limitations

Initial TUI control is intentionally serial: only one runner per TUI, streaming previews for this TUI’s worker, no direct interruption of an in-progress model call, and no interactive control of another process that happens to be running a session. Read-only observation of external sessions remains possible. The underlying CLI remains available. A per-session OS lock prevents concurrent CLI/TUI execution of the same session; competing resumes are rejected without changing the owner's state.

If a worker disconnects, its pending approval dialog is discarded and the TUI reports the loss. Use `/recover` (or CLI `recover-session SESSION_ID`) after inspecting history. Recovery refuses a live owner, preserves saved grants, and never replays an unanswered approval or automatically resumes work. If a native write was interrupted, run `recover-writes` afterward before resuming. Completed sessions remain completed even if the worker died during final ownership cleanup.

Approval choices and restoration actions retain their existing security semantics. The TUI requires an interactive terminal and uses Ratatui's terminal restoration. Raw events may contain private project information.

The Ratatui/Crossterm dependency versions are locked in `Cargo.lock`. The [decision log](16-decision-log.md) captures the keyboard rationale, and the [smoke-test guide](17-smoke-test.md) covers the related manual exercise.

## Human checkpoints and step-result review

Human workflow steps use a **Human checkpoint** screen with the review question, pinned input documents and Approve & continue (`y`) / Decline (`n` or Esc). There are no reusable tool grants. Tab/Shift+Tab or Left/Right selects a document; Enter, `e` or Full evidence opens its exact recorded version and the full question. The overview labels excerpts explicitly. At narrow supported sizes it preserves the selected document name; smaller-than-supported approvals cannot be accepted.

The evidence reader is read-only: `y`/`n` and Enter never decide, arrows/page keys scroll, C copies the full selected evidence, and Esc returns to the same review. Help can open above it and returns without answering the pending question. An approval applies to the **complete pinned input selection**, not just the selected document. Before sending approval, the TUI rechecks the live owner, session/branch/step/attempt, input manifest and displayed document bodies/versions. Changed or unavailable evidence removes the approving control; Decline remains available. The engine remains responsible for reselecting **all** inputs and validating the complete selection before recording `human.approved`, including newly matching inputs not previously displayed.

Human result verification has the separate **Review step result** title. It shows available recorded result artifacts, which are not a pinned-input approval contract; the backend records `verification.human`. Missing result artifacts stay explicit. Sending either decision is acknowledged as awaiting the engine’s recorded outcome, not as proof that the goal was achieved. A decline follows the workflow’s configured handling. Request expiry/worker loss cannot restore old decision controls. Legacy human prompts without typed metadata retain their generic presentation rather than inferring provenance from text.

## Approval command emphasis and former turn-limit diagnostics

Shell permission and persistent-grant confirmation panes show the exact command in a separate bold cyan block, with scope/location in yellow and sandbox context in gray. The command comes from typed request metadata; model text cannot change available approval choices or grant matching. Multiline commands, arguments and operators remain visible in the scrollable request. Nonprinting control/format characters are escaped in the command preview; the engine receives the original unchanged command.

A recorded `step hit limit of 16 model turns` diagnostic means an older engine stopped that attempt after 16 coding responses. Responses can request tools, register artifacts or need protocol correction; this count is not exclusively tool calls. The fixed model-turn cutoff has been removed, including for existing configurations containing legacy `max_turns`/`max_turns_per_attempt`. Existing historical diagnostics remain evidence of the old attempt. After upgrading, dismiss with Esc and use `i`, `/resume`, Enter to retry the blocked step as a new attempt. Explicit cancellation, provider failures, verification, configured deviation retry bounds and the workflow transition guard still apply.

## Completed-run results and recorded source edits

When a selected run completes (or a completed session is first loaded), the Activity view opens a result panel. `s` reopens it; the completed session’s Activity footer also shows **[s] Overview**, reachable by mouse or Tab/Enter. More exposes the same action from other workspace tabs; artifact readers show it directly. Activity controls display `[Enter] Open selected`, `[i] Compose`, `[s] Overview` and `[.] More`; period opens More outside text inputs. On narrow terminals Compose and secondary actions move to More, and compact labels retain their key badges. Overview remains present and highlighted while its screen is open. The overview-specific `o`/`e` shortcuts invoke the same report/full-result actions as their buttons. `H`, Escape or Enter returns to activity. The overview separates a three-line, attributed conclusion excerpt, final-step verification scope and the recorded native-edit count. It does not dump the report body into the overview. Read final report opens the exact historical version; Review edits opens recorded diffs; More → Full result preserves the complete summary/report evidence. Step summaries/reports are labelled model-authored. Completion means control flow reached the end, not that performance improved or the user's objective was independently validated. `verification: none` displays “no checks required”; its aggregate pass is not a substantive test. Artifacts replaced after completion do not rewrite the report for that run.

Press **3** for **Edits**. Multiple changed files open an All files overview; one changed file opens its diff directly. The overview retains all recorded paths, including no-net-change/restored paths, and distinguishes recorded-path counts from net changes. Tab/Shift+Tab cycles All files and changed-file views; arrows select overview rows or scroll the current diff. Enter focuses action controls without activating one. In controls, Tab/arrows move focus, Enter activates an ordinary action, and Esc returns to review. Click a row or use Open selected diff to inspect that exact path. On narrow terminals secondary navigation stays in More; no function keys or Git shortcuts are required.

The net recorded diff compares first recorded pre-edit contents to latest recorded state, including previous explicit restores; it is not a fresh disk comparison. Added/deleted lines retain `+`/`-` prefixes and green/red styling. Shell/manual changes are outside this journal, and artifacts remain documents. Missing snapshots and history gaps are explicit errors rather than empty-success states. C/E exports preserve the full overview or selected diff beyond preview limits.

Keep file / Keep all saves review intent for the already-applied recorded revisions. It changes no source files, tool permissions, verification verdicts, workflow status or Git state; unkept changes are not automatically reverted. Marks persist as `edits.kept` events scoped to session, branch, path and exact native-edit revision. New writes/restores invalidate the earlier revision mark, even when their contents happen to match; a fork requires its own review. Keep rechecks snapshot availability, recorded history and current disk contents while holding the idle-session and native-write guards. Keep all includes off-screen changed paths and refuses the entire review when an included path has drift/gaps/unavailable snapshots; it never silently skips a conflict. An unrelated drifted file does not block Keep file. A displayed Kept revision is a historical review marker, not a claim of live disk validation after later manual edits.

- `u`: preview reverting the selected file.
- `U`: preview reverting all recorded files.
- `y` or the explicit Revert button: apply a fresh preview; `n`/Escape or Cancel cancels. Enter and held/repeated confirmation keys never authorize a revert. Help captures decisions above the preview. Under 40×20 the preview stays pending but acceptance controls are hidden/disabled; Escape still cancels. Session/branch/history changes expire a preview and require preparing another one.

Revert restores the original contents recorded before the session first touched each selected file, preserving any pre-existing manual work in that snapshot. It deletes files originally created by the model. It uses the existing guarded restore engine: execution must be idle, no writes may need recovery, history/branch and current contents must still match the preview, and sensitive/symlinked paths remain forbidden. Per-file revert checks only the selected path's history/current state; unrelated manual drift does not prevent that file's revert. Revert-all preflights all tracked paths before writing. Manual edits are never force-overwritten.

Reverting changes workspace files and appends restoration records; it does not fork/resume the workflow or erase its artifacts/history. The result then states that its report/checks describe the earlier run, not the restored workspace. This covers tracked native UTF-8 writes, not arbitrary shell/manual changes, Git operations, service state or external effects. Multi-file restore retains the existing partial-failure/crash limitations in [workspace restoration](09-workspace-restore.md); failures report what happened rather than claiming atomic undo.

## Mouse, paste and layout

Mouse capture is enabled by default for this TUI process. Click tabs, workspace actions, More entries, session/activity/artifact rows or the explicit approval-choice rows; keyboard paths use the same routing and guards. Press and release must target the same current control. Resizes, request replacement and layer changes invalidate stale targets. Wheel events navigate/scroll the active region (or the hovered listed row's region). Click inside a focused editor to place its caret.

Open Help (`h`/`?`) and use Toggle mouse or `M` to release capture for terminal text selection; the setting is memory-only. Bracketed paste inserts literal text into the focused editor/search field, respects its size limit and never submits. Terminals must support bracketed-paste delimiters to distinguish a paste from keystrokes. Capture and cursor settings are restored on exit and suspended for the external editor.

The composer and sidebar are not permanently allocated. Activity/artifact/native-edit inspection opens deliberately; the workspace action row replaces the old full static key legend. Blue input, cyan focus, neutral model output, scoped green outcomes, amber attention and red errors/destructive actions have separate roles.

The compact workspace, focused readers, All-files/file cycling, revision-scoped Keep, explicit session candidates and distinct empty/error states are implemented. Generating every Help entry from shared action definitions and further visual refinements remain follow-up work. Typed decisions, native restoration guards and accounting contracts remain authoritative.

## Rendered presentation and contextual controls

The TUI uses a shared dark background/panel palette and rounded, framed action buttons, with an accent border/text for primary actions. Only the keyboard-focused control receives a solid cyan fill and a `›` marker. The active Overview button stays visible with bold cyan text and a double border; this current-view state is separate from keyboard focus. The active main tab uses a separate selection style. The bottom row depends on the current screen: results expose `[o] Read final report` (or `[e] Full result`), `[3] Review edits`, `[s] Overview` and `[.] More`; artifacts expose Open selected / Versions / More, or Back / Versions / More while reading. ## Creation and explicit-purpose messaging

New session uses readable workflow titles/roadmaps and a full goal editor. Browsing never creates a session or calls a model. Continue/Start workflow, Back, Clear draft and Cancel have matching keyboard/mouse paths. Goals are revalidated before creation; duplicate Enter repeats cannot start a second session.

Compose opens an editor with a visible target and effect. Change recipient switches Step/Manager drafts when step delivery is eligible. A completed/running/interrupted session offers manager questions or Commands rather than a live-step delivery promise. Sending step instructions rechecks persisted branch/step, ownership and unfinished writes; a refusal keeps the draft. The read-only manager saves the question before inference, and More → Manager replies opens its saved exchange. A reply to another scope is identified as belonging to its original session/branch. Stop manager cancels its active provider call and retries; it does not stop a coding worker. Remote billing may remain uncertain.

Letters and slash-prefixed text remain literal in Step and Manager messages. From navigation, `/` opens **Commands**, the explicit control-command interface. Mode switches retain separate memory-only drafts, including by branch. Tab/Shift+Tab reaches Send, recipient controls and header Help without submitting; Escape from controls returns to editing, then Escape closes with the draft retained. Small terminals use a full-width editor. A sent step instruction can be restored for review through More → Restore instructions for the same scope, without automatically resending or overwriting another draft.

## Complete conversation dump

**More → Conversation dump** or Commands **/dump** opens a read-only snapshot of every recorded event on this branch and its ancestry, including full tool arguments/results, raw model responses, protocol errors and provider failures. Long bodies show previews. **[R] Refresh** captures new evidence; **[w] Save full dump** writes complete Markdown to `.greenlight/exports/`; Copy retains the complete content. New requests include exact prepared messages; older runs label missing payloads. A locally owned runner can contribute an explicitly unvalidated live-buffer snapshot. See [format, CLI commands and limits](35-conversation-dump.md).

## Retry a failed provider request

A live workflow provider failure opens **Provider request paused**, with **[y] Retry request**, **[n] Stop for now**, and Esc to hide without answering. Retry keeps the exact messages, current attempt and branch; earlier tools are not replayed. Fix credits/connectivity or wait for a rate limit, then retry; any remaining provider cooldown is honored. Billing uncertainty remains visible for timeouts/server errors. **[a] Review retry** returns to a hidden popup. If the worker has stopped and a saved checkpoint exists, **[t] Retry saved request** validates the workspace and restores the exact messages and original attempt. This survives reopening the app; recover an interrupted owner first. **[T] Retry saved manager** in More restores a saved side question. Without a checkpoint, **[t] Continue step** starts a fresh attempt and warns that earlier tools may run again. See [retry behavior and limits](19-provider-failures.md#explicit-retry-in-the-workflow-tui).

Workspace shortcuts, button labels and the Help action reference share typed command metadata. Buttons invoke commands directly. ## Inspecting the provider and API key

Open **[c] Details → Provider / API key**, or use the Provider button on the Usage page / More menu. If a tool/provider popup owns input, first press Esc to hide it without deciding. The Provider page shows endpoint origin, configured default model, API-key variable, masked key and credential source. Normal keys show the first five and last five characters; keys of ten characters or fewer, empty values and invalid values do not expose their contents. URL credentials, paths and query strings are excluded from the origin display.

For this TUI's running/paused workflow, the page uses the worker's captured credential and latest requested model. Initialization gaps are explicit. Without that worker, it shows the viewer process's current configuration and says that this is not a historical request or another process's credential. Credential metadata is ephemeral: it is not added to usage records, events or conversation dumps. Explicitly copying the Provider page copies only its masked text.

The inherited process environment wins over `.greenlight/.env`, which wins over the project's `.env`. An existing empty variable also overrides files. Dotenv files are loaded at process startup without overriding existing variables; editing them does not reload a running process. Provider construction captures the selected key, so an exact-request retry retains it. Restart Greenlight after changing credentials. For the default variable, `env -u DEEPINFRA_API_KEY greenlight` starts without the shell override and allows a project dotenv file to supply it; this does not edit the shell or any project file.


### Stop execution

`k` and the visible **[k] Stop** action cancel an active provider request, retry wait or sandboxed shell command. `q` remains Quit and is blocked while a worker is active. Arrow keys navigate; j/k/l are not navigation aliases. In text fields letters remain literal; modal decisions and Help retain input ownership. Close a permission popup with Esc before stopping from the workspace; stopping a hidden pending approval does not record a denial. Source writes already applied remain, and a synchronous journaled write finishes before stopping. Cancelling an HTTP request cannot guarantee cancellation of remote processing/billing. Cancelled commands may have partial effects and are never automatically replayed. Continue starts a fresh attempt.

Provider errors retain bounded redacted diagnostics. More → Provider displays the latest recorded error body and support request IDs; Usage → Request details displays the error for that exact dispatch, including other session branches. Copy exports the displayed evidence. The live retry popup includes scrollable diagnostics; Esc hides it without deciding. Recognized busy-capacity failures are labelled Model busy, and priority service is shown when explicitly configured. Older discarded bodies cannot be recovered.


## Project ownership

One workflow executes per project, across CLI/TUI clients. An amber **Project busy** header is separate from the selected session's status. **[O] Open owner** navigates to the owning session; **[R] Refresh project** checks again without starting anything. Exact approval/input waits can be unknown in another client. Browsing, exports and manager questions remain available. Stop is available through the owning worker's existing control handle; it frees ownership only when that worker actually finishes.

A new goal created while busy stays saved as a Ready session with **Created; not started** feedback. A refused step submission retains its draft; a later worker claim race restores unsent instructions to their original draft scope. No automatic queue or delayed dispatch is created. Interrupted maintenance also offers explicit owner recovery, even when the session was not Running. After owner recovery, pending native writes still require reconciliation. See [project coordination](41-project-execution-coordination.md).
