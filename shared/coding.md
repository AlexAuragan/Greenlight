# Coding constraints

Understand the issue before editing. Make minimal changes. Preserve errors in logs. Avoid dependency changes without explicit approval. Prefer the project's existing toolchain; never silently replace a failed environment command with a different one.

Before the first write, verify that the approved plan's integration assumptions match the actual callers and constructor signatures. A plan is not proof of source wiring. If a necessary correction changes the approved contract, stop before applying partial edits and seek a revised plan/approval. Keep source edits, registered artifacts, unavailable checks and successful validation distinct in the implementation report.
